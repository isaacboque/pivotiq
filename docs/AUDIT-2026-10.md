# pivotiq audit — 2026-10

Branch `audit/2026-10`, created from `training`. `main` was not touched and nothing was pushed or merged.
No metrics are claimed anywhere in this document.

## Is vs Should-be
**Should-be** (vault `Projects/Future Analytics.md`, README "Milestone 1 / stub pipeline"): the clean successor of the
legacy futsal-analytics tool — typed models, geometry, a CLI, a training workflow for ball + keypoint detectors, and a
pipeline that goes from stub to real as milestones land.
**Is**: exactly Milestone 1. `src/pivotiq` has models, config, pitch geometry and a CLI whose `analyze` prints the run
configuration and does not process video. The legacy `src/futsal_analytics` package, a root-level `futsal_analyzer_v2.py`,
a Streamlit `web/` app and generated outputs sit in the same tree, which blurs what is "PivotIQ".

## Baseline
No venv exists for this repo; the audit ran on the global Python (3.11) with the packages already installed.
**Caveat discovered**: the global environment has `futsal_analytics` installed editable from *another checkout* (IAFS),
so `pytest` was importing that tree, not this one. The first baseline (192 passed / 2 failed) was therefore a test of IAFS code.
After setting `pythonpath = ["src"]` in `pyproject.toml` the suite tests this tree.
`ruff` was not installed; it was `pip install`ed into the global Python (not into a project venv — see Needs you).
Pre-existing ruff findings on the current ruff version: 16 (unused imports, import order, quoted annotations, unused unpacked vars).

## Findings, ranked
1. **Team classification could never train (regression).** `get_jersey_color_features` was changed to a 4-vector
   `[sin H, cos H, S, V]`, but `train_teams` still gated on `var(features[:, 0]) < 50` — a threshold from the era when column 0 was
   raw hue (0–180). On a mean of sines (range [-1, 1]) the variance is always < 50, so K-Means never ran and every player got team 0.
   *Fixed*: the gate is now the summed feature variance against `MIN_FEATURE_SPREAD = 0.06` (the same cut-off expressed in
   angle terms). Same bug exists in IAFS's `detection.py` (identical file); not fixed there in this item.
2. **K-Means features were on different scales** (sin/cos in [-1, 1] vs S, V in 0–255), so hue was effectively ignored — which defeats
   the wraparound fix the docstring describes. *Fixed*: S and V are divided by 255. **This changes clustering behaviour**; it has
   only been checked on synthetic kits (red vs blue vs yellow referee, white vs black, identical kits refused), not on real footage.
3. **Two stale tests** (expected a 3-vector) — updated to the 4-vector contract; added tests for the wraparound, unit range, gating
   and train/predict separation.
4. **Config accepted nonsense**: unknown keys raised a bare `TypeError`, typos in section names were silently ignored, wrong types and
   out-of-range values passed (confidence 9, `min_visible_keypoints = 1`). *Fixed*: `ConfigError` with the offending key,
   unknown sections/keys rejected, type + range validation. 36 tests.
5. **CLI**: invalid `--device`, non-positive `--max-frames`, a directory passed as video and bad config produced either a traceback or
   silent acceptance. *Fixed*: exit 2 (usage/config) or 1 (input file) with a one-line message.
6. **Homography**: singular / NaN / inf matrices were accepted; `pixel_to_pitch` returned `inf`/`nan` for points mapping to infinity;
   `pitch_to_pixel` raised `LinAlgError` deep inside numpy. *Fixed*: validated at construction; projection raises `ValueError`.
7. **Hygiene**: 77 generated files were tracked (`out/`, `out_smoke/`, `runs/` — training curves and batch images). *Fixed*:
   `runs/` added to `.gitignore` (`out*` was already listed), files `git rm --cached` (still on disk). Large history remains.
8. **Docs/CI**: README test count (70) was stale; CLAUDE.md was untracked — now committed. CI already ran ruff + pytest on 2 OS x 3 Python
   versions; with `pythonpath` it now also works when another editable install exists.

## Decisions taken (smallest reasonable choice)
- Fix the K-Means gate and scaling in the legacy `futsal_analytics` package rather than leave a broken team classifier in the "successor" repo.
- Reject unknown config keys (strict) because a silent typo in a threshold is worse than a startup error.
- No typing/mypy config added: the repo's existing ruff config is the standard; mypy would need a larger triage than this pass.
- `Homography` now validates determinant `|det| >= 1e-12`; a very ill-conditioned but valid H still passes (tested).
